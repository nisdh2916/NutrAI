## 1. 전체 평가

현재 슬라이드는 시각적으로 깔끔하고, 앱 화면과 데이터 흐름이 잘 보인다. 특히 시스템 아키텍처, 사용자 흐름, RAG 추천 파이프라인은 발표 자료로 계속 가져가도 좋다.

다만 최종 발표 기준으로는 다음 4가지가 부족하다.

1. **식사량 기준 설명 부족**  
   교수님이 질문한 1인분/100g/1회 제공량 기준이 슬라이드에 직접 보이지 않는다.

2. **AI 구현 범위가 섞여 보임**  
   YOLO 학습 데이터, 식약처 영양 DB, Qwen3, RAG, 파인튜닝 여부가 한 흐름 안에 있어 역할이 혼동될 수 있다.

3. **추천 시나리오가 아직 단순함**  
   "추천 메뉴 3개"보다 "현재까지 섭취한 영양소 불균형을 분석한 뒤 추천한다"는 흐름이 더 강하게 보여야 한다.

4. **구현 현황 표현이 과장으로 보일 위험**  
   `완료 항목 9/9`와 `향후 계획 Q1 음식 인식 모델 연동`이 동시에 있어, 무엇이 완료이고 무엇이 검증 중인지 질문받을 수 있다.

## 2. 슬라이드별 수정 지시표

| 기존 슬라이드 | 현재 내용 | 조치 | 수정 방향 |
|---------------|----------|------|-----------|
| 1 | 표지 | 수정 | 한 줄 정의를 "AI 개인 맞춤 식단 관리"에서 "섭취 영양소 분석 기반 개인 맞춤 추천"으로 구체화 |
| 2 | 왜 NutrAI인가 | 유지+수정 | Problem 02를 "질환·알레르기·섭취 현황을 반영한 추천 부족"으로 강화 |
| 3 | 시스템 아키텍처 요약 | 재구성 | "시스템 설계 원칙" 슬라이드로 변경하거나 4번과 통합 |
| 4 | 시스템 아키텍처 그림 | 유지 | 교수님이 좋게 본 데이터 흐름도. 설명은 1분 이내로 줄이기 |
| 5 | 사용자 시나리오 | 대폭 수정 | 6단계 기능 나열 대신 "하루 식사 흐름" 기반 시나리오로 변경 |
| 6 | 회원가입 & 온보딩 | 수정 | BMR을 "자동 계산"보다 "추정"으로 표현. 나이·성별·활동량·추후 인바디 보완 추가 |
| 7 | 식사 기록 | 수정 | YOLO와 식약처 DB 역할 분리 문구 추가. 사용자 섭취량 보정 UI 강조 |
| 8 | 식단 분석 & 리포트 | 대폭 수정 | 단순 리포트 화면보다 "현재까지 섭취 영양소 분석" 화면으로 강조 |
| 9 | 맞춤 추천 알고리즘 | 분할 권장 | RAG 파이프라인과 동적 프롬프트/추천 결과 예시를 분리 |
| 10 | 알레르기 필터링 | 유지+수정 | 안전 검증 사례로 유지. "필터링 전후" 구조는 좋음 |
| 11 | AI 채팅 코칭 | 축소 | 핵심 발표 시간이 부족하면 UI 시나리오 안에 포함. 단독 슬라이드는 선택 |
| 12 | 기술 스택 | 병합 | 단순 기술 나열 대신 "구성요소별 역할과 직접 구현 범위" 표로 변경 |
| 13 | 구현 현황 & 향후 계획 | 대폭 수정 | 완료/검증 중/향후 개선으로 분리. 과장 표현 제거 |
| 14 | Q&A | 유지 | 그대로 사용 가능 |

## 3. 새로 추가해야 할 슬라이드

### 추가 1. 영양성분 계산 기준

**넣을 위치:** 식사 기록 슬라이드 다음  
**목적:** "식사량 기준은 1인분인가요?" 질문에 선제 대응.

구성 예시:

| 항목 | 설명 |
|------|------|
| DB 기준량 | 식약처/공공 영양성분 DB의 기준량 사용 |
| 앱 계산 | 기준 영양성분 × 사용자 섭취량 보정값 |
| 보정 방식 | 0.5인분, 1인분, 1.5인분 또는 직접 수정 |
| 한계 | 사진만으로 정확한 중량 추정은 어려움 |
| 개선 | 추후 식사량 추정 모델 또는 사용자 보정 UX 강화 |

슬라이드 문장:
> 사진 인식은 음식 종류를 찾고, 실제 영양 계산은 DB 기준량과 사용자 보정 섭취량을 결합해 산출합니다.

### 추가 2. 동적 프롬프트 예시

**넣을 위치:** 맞춤 추천 알고리즘 다음  
**목적:** 사용자 정보와 섭취량에 따라 프롬프트가 바뀌는 것을 보여줌.

포함 변수:
- 목표 칼로리
- 현재 섭취 칼로리
- 탄수화물/단백질/지방/나트륨 섭취량
- 알레르기
- 질환
- 선호/비선호 음식

구성 예시:

```text
[사용자 정보]
- 목표: 체중 감량
- 질환: 고혈압
- 알레르기: 견과류
- 목표 섭취량: 1,800 kcal

[오늘 섭취 현황]
- 현재 섭취: 1,230 kcal
- 단백질: 부족
- 나트륨: 높음

[요청]
저녁 식단을 추천하되, 저염/고단백 기준을 우선하고 견과류 포함 음식은 제외해줘.
```

### 추가 3. 영양소 불균형 분석 기반 추천

**넣을 위치:** 동적 프롬프트 다음  
**목적:** 추천 시나리오가 간단하다는 피드백 보완.

추천 결과 구조:
1. 현재 섭취 요약
2. 부족/과다 영양소 분석
3. 추천 메뉴
4. 추천 이유
5. 알레르기/질환 안전 검증

슬라이드 예시 문장:
> 오늘은 탄수화물은 충분하지만 단백질이 부족하고 나트륨이 높은 상태입니다. 따라서 저염 고단백 식단을 우선 추천합니다.

### 추가 4. AI 구현 범위 및 파인튜닝 여부

**넣을 위치:** 기술 스택/구현 현황 근처  
**목적:** 교수님이 질문한 "본인이 한 것"을 명확히 정리.

| 구성요소 | 역할 | 구현 범위 | 파인튜닝/학습 여부 |
|----------|------|-----------|-------------------|
| YOLOv11 | 음식 객체 탐지 | 이미지 입력, 탐지 결과 처리, 수정 UX | 실제 학습 여부 명시 |
| 식약처 DB | 영양성분 근거 | 음식명 매칭, 영양소 조회 | 모델 학습 데이터 아님 |
| ChromaDB/KR-SBERT | RAG 검색 | 영양 정보 임베딩, top-k 검색 | 임베딩 기반 검색 |
| Qwen3 | 파싱/추천 문장 생성 | 프롬프트 구성, 스트리밍 응답, 후처리 | 파인튜닝 여부 명시 |
| 후처리 로직 | 안전 검증 | 알레르기/칼로리 범위 재검증 | 직접 구현 로직 |

## 4. 최종 발표 추천 흐름

기존 14장을 기반으로 최종 발표는 아래 순서가 가장 안정적이다.

| 최종 순서 | 슬라이드 | 기반 |
|----------|----------|------|
| 1 | 표지: 섭취 영양소 분석 기반 AI 식단 추천 | 기존 1 수정 |
| 2 | 필요성: 기록의 번거로움 + 개인화 추천 부족 | 기존 2 수정 |
| 3 | 해결 방향: 사진 인식 + 영양 DB + RAG 추천 | 기존 3 재구성 |
| 4 | 시스템 아키텍처 | 기존 4 유지 |
| 5 | 데이터 흐름 요약 | 기존 3/4 일부 재활용 |
| 6 | 사용자 시나리오: 하루 식사 흐름 | 기존 5 대폭 수정 |
| 7 | 온보딩: 개인화 추천을 위한 입력 | 기존 6 수정 |
| 8 | 식사 기록: YOLO 탐지와 사용자 보정 | 기존 7 수정 |
| 9 | 영양성분 계산 기준 | 신규 |
| 10 | 식단 분석: 현재 섭취 영양소 누적 | 기존 8 수정 |
| 11 | RAG 기반 맞춤 추천 파이프라인 | 기존 9 수정 |
| 12 | 동적 프롬프트 예시 | 신규 |
| 13 | 영양소 불균형 기반 추천 결과 | 신규 |
| 14 | 알레르기/질환 안전 검증 | 기존 10 유지 |
| 15 | AI 채팅 코칭 또는 UI 전체 흐름 | 기존 11 축소 |
| 16 | AI 구현 범위와 파인튜닝 여부 | 기존 12/13 재구성 |
| 17 | 구현 현황, 한계, 개선 방향 | 기존 13 수정 |
| 18 | Q&A | 기존 14 유지 |

20분 발표라면 18장은 많아 보일 수 있지만, 아키텍처와 Q&A는 짧게 넘기고 시나리오 중심으로 말하면 가능하다. 시간이 부족하면 기존 11번 AI 채팅 코칭 슬라이드를 삭제하고 17장으로 줄인다.

## 6. 슬라이드별 발표 멘트 수정 포인트

### 기존 6번 온보딩 슬라이드
현재 `몸무게 65kg → LLM 추출 → Mifflin-St Jeor → 목표 1,800 kcal` 흐름은 키/몸무게만으로 계산하는 것처럼 보일 수 있다.

수정 멘트:
> 온보딩에서는 나이, 성별, 키, 몸무게, 활동량, 알레르기, 질환 정보를 구조화합니다. 현재 권장 섭취량은 이 정보를 바탕으로 추정하며, 향후 인바디 정보를 추가해 더 정밀하게 보완할 수 있습니다.

### 기존 7번 식사 기록 슬라이드
`YOLOv11 + 식약처 DB`가 한 줄에 붙어 있어 식약처 데이터로 YOLO를 학습한 것처럼 들릴 수 있다.

수정 멘트:
> YOLO는 이미지에서 음식 후보를 탐지하고, 이후 탐지된 음식명을 식약처 영양성분 DB와 매칭해 칼로리와 탄단지 정보를 가져옵니다. 두 데이터는 역할이 다릅니다.

### 기존 9번 맞춤 추천 알고리즘 슬라이드
파이프라인은 좋지만 추천 결과가 왜 개인화되는지 한 번 더 보여줘야 한다.

수정 멘트:
> 추천은 단순히 음식명을 생성하는 방식이 아니라, 사용자 프로필과 오늘 섭취량을 입력으로 받아 부족하거나 과한 영양소를 먼저 분석한 뒤 메뉴를 제안합니다.

### 기존 13번 구현 현황 슬라이드
완료와 향후 계획의 경계가 모호하다.

수정 멘트:
> 구현 완료 항목, 검증 중인 항목, 향후 개선 항목을 분리해 설명드리겠습니다. 특히 모델 성능 검증과 식사량 추정은 향후 개선 과제로 남아 있습니다.

## 7. 결론

현재 PPT는 디자인과 큰 흐름은 충분히 좋다. 최종 발표에서는 새 디자인을 다시 만드는 것보다, 아래 네 가지를 보강하는 것이 가장 효과적이다.

1. 식사량 기준 슬라이드 추가.
2. 사용자 하루 시나리오를 더 구체화.
3. 영양소 불균형 분석 후 추천하는 구조를 보여주기.
4. AI 구성요소별 역할과 파인튜닝 여부를 솔직하게 표로 정리.

원본 PPTX가 있으면 이 구조를 기준으로 실제 슬라이드 문구와 배치까지 직접 수정할 수 있다.
