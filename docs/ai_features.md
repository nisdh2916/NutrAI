# NutrAI AI 기능 상세 문서

> 발표·설명용 레퍼런스. 파인튜닝 여부·데이터 출처·각 기능의 동작 방식을 기술합니다.

---

## 1. AI 스택 한눈에 보기

| 구성요소 | 선택 | 이유 |
|---|---|---|
| **LLM** | Qwen3:8b (Alibaba) | 8B 파라미터, 한국어 우수, 로컬 실행 가능 |
| **추론 엔진** | Ollama | Windows/Mac 로컬 GPU/CPU 서빙, API 호환 |
| **임베딩 모델** | KR-SBERT | 한국어 특화 Sentence-BERT, 40K 어휘 |
| **벡터 DB** | ChromaDB (로컬) | 외부 서버 불필요, 영구 저장, L2 거리 검색 |
| **프레임워크** | FastAPI + LangChain | 비동기 스트리밍(SSE), Ollama 직접 HTTP 병용 |
| **파인튜닝** | **없음** | RAG + 프롬프트 엔지니어링으로 대체 |

> **파인튜닝을 하지 않은 이유**  
> Qwen3:8b는 사전학습 단계에서 한국어 영양·식단 도메인 지식을 이미 충분히 보유합니다.  
> 파인튜닝 대신 **RAG**로 최신 식품 DB를 실시간 주입하고, **시스템 프롬프트**로 답변 형식과 안전 규칙을 제어합니다.  
> 이 방식은 데이터셋 구축 비용 없이 DB 업데이트만으로 성능 개선이 가능합니다.

## 2. 학습 데이터 (RAG 벡터 DB)

파인튜닝 데이터가 아닌 **검색용 지식 베이스**입니다. Qwen3:8b가 답변을 생성할 때 이 DB에서 관련 문서를 가져와 컨텍스트로 활용합니다.

### 2-1. 데이터 출처

| 데이터 | 출처 | 레코드 수 | 용도 |
|---|---|---|---|
| 일반 식품 영양성분 | 국가표준식품성분표 (농촌진흥청) | **19,495건** | 기본 식품 칼로리·영양소 |
| 가공식품 영양성분 | 식품의약품안전처 식품영양성분 DB | **277,074건** | 시판 제품 영양 정보 |
| 건강기능식품 | 식약처 건강기능식품 DB | 별도 컬렉션 | 영양제·보충제 추천 |
| 영양 가이드라인 | 한국인 영양소 섭취기준 (KDRi) | PDF 파싱 | 질환별·연령별 권고 기준 |

### 2-2. 벡터 임베딩 방식

```
음식명 + 카테고리 + 영양정보 → 텍스트 변환
        ↓
snunlp/KR-SBERT-V40K-klueNLI-augSTS
        ↓
768차원 벡터 → ChromaDB 저장
```

- 모델: `snunlp/KR-SBERT-V40K-klueNLI-augSTS`
- KLUE NLI 데이터로 증강 학습된 한국어 Sentence-BERT
- L2 거리 기준 유사도 검색 (임계값 `1.0` ≈ cosine 유사도 0.5)

### 2-3. 메타데이터 태그 (필터링용)

ChromaDB 각 문서에는 아래 boolean 플래그가 저장되어 카테고리 필터링에 사용됩니다.

| 태그 | 조건 |
|---|---|
| `is_diet` | kcal ≤ 300 & 비다이어트 카테고리 제외, OR 고단백(≥15g)+저지방(≤8g) |
| `is_diabetes` | 당류 ≤ 5g & 탄수화물 ≤ 30g & 고당 카테고리 제외 |
| `is_hypertension` | 나트륨 ≤ 300mg & 고염 카테고리(젓갈·김치·장류) 제외 |
| `is_supplement` | 건강기능식품 소스일 때만 True |
| `is_morning/lunch/dinner/snack` | 카테고리 집합 매핑 |

## 3. AI 기능별 상세 동작

### 3-1. AI 코치 채팅 (`mode: chat`)

**위치:** 앱 하단바 → 채팅 버튼

**목적:** 사용자가 자유롭게 식단 질문을 하면 개인화된 답변을 실시간 스트리밍으로 제공

**파이프라인:**

```
사용자 질문
    ↓
① 전처리 (의도·시간대 감지)
    "저녁 추천" → meal_time="저녁"
    ↓
② 다중 쿼리 재작성 (최대 4개)
    쿼리1: 원문
    쿼리2: "다이어트 저녁 메뉴"
    쿼리3: "당뇨 맞춤 식단 가이드라인"
    쿼리4: "남은 800kcal 이하 저녁 식사"
    ↓
③ ChromaDB 다중 검색 (k×2 후보 → 유사도 필터 → 알레르기 제거 → 상위 5개)
    ↓
④ 구조화 프롬프트 조합
    [사용자 정보] + [식단 현황] + [참고 영양 정보(DB 검색 결과)] + 질문
    ↓
⑤ Qwen3:8b SSE 스트리밍 (temperature=0.6, max_tokens=2048)
    ↓
⑥ 후처리: <think> 제거, 칼로리 검증(⚠️), 알레르기 이중 확인
    ↓
Flutter SSE 수신 → 실시간 텍스트 출력
```

**시스템 프롬프트 핵심 규칙:**
- DB에 있는 음식만 추천 (브랜드·가공식품 금지)
- 칼로리 수치는 [식단 현황]에서 가져와 임의 계산 금지
- 당뇨: 단백질이 아닌 탄수화물·당류 제한 강조
- 고혈압: 지방이 아닌 나트륨 제한 강조

---

### 3-2. 추천 메뉴 (`/recommend`)

**위치:** 앱 하단바 → 추천 탭

**목적:** 다이어트·질환맞춤·기호별 카테고리별로 JSON 형태로 메뉴 3개 추천

**파이프라인:**

```
사용자 프로필 + 카테고리 선택
    ↓
① 카테고리별 쿼리 생성
    다이어트: "저칼로리 고단백 체중 감량 식단"
    질환맞춤: "{질환명} 맞춤 식단 가이드라인"
    건강기능식품: "비타민 미네랄 건강기능식품"
    ↓
② ChromaDB where 필터 + 벡터 검색 병행
    {"is_diet": true} + 유사도 검색 → 후보 추출
    ↓
③ Qwen3:8b JSON 생성 (format: "json", temperature=0.4)
    → {"items": [{"name": "...", "kcal": 300, "reason": "..."}]}
    ↓
④ validate_and_rank_items()
    알레르기 항목 제외 → 남은 칼로리 초과 항목 필터
    → 단백질/칼로리 스코어링 → 상위 3개
    ↓
Flutter → 카드 UI로 렌더링
```

**temperature=0.4를 쓰는 이유:** JSON 구조가 흔들리지 않도록 결정적 출력 우선. 창의성보다 안정성.

---

### 3-3. 리포트 AI 분석 (`mode: report`)

**위치:** 리포트 탭 → 일간·주간·월간

**목적:** 식단 기록 데이터를 요약 분석해 2~4문장 평문으로 인사이트 제공

**채팅(mode=chat)과의 차이점:**

| | 채팅 (chat) | 리포트 (report) |
|---|---|---|
| RAG 검색 | O (ChromaDB 조회) | X (생략) |
| 시스템 프롬프트 | 음식 추천 형식 강제 | 평문 분석 형식 강제 |
| 마크다운 | 허용 (`**음식명**`) | 완전 금지 |
| 출력 형식 | 음식 3개 + 코칭 메시지 | 3~4문장 통합 분석 |
| temperature | 0.6 | 0.6 |

**리포트 프롬프트에 포함되는 데이터:**

```
[사용자 정보] 나이, 성별, 키, 몸무게, 건강 목표, 질환, 알레르기
[분석 요청]   "이번 주 평균 섭취 칼로리 XXXX kcal / 탄수화물 XXg ..."
```

**데이터 충분성 조건 (데이터 부족 시 AI 카드 숨김):**
- 주간: 데이터 있는 날 3일 이상
- 월간: 데이터 있는 날 7일 이상

**일간 프롬프트 예시:**
```
오늘 식단: 아침-현미밥(320kcal), 점심-김치찌개(450kcal)
총 섭취: 770kcal / 목표: 1800kcal / 남은 칼로리: 1030kcal
탄수화물 98g / 단백질 32g / 지방 18g
→ 전체 영양 밸런스와 저녁 식사 방향을 3문장으로 분석해줘.
```

### 3-4. 오늘의 맞춤 팁 (홈 화면)

**위치:** 홈 화면 상단 배너

**목적:** 오늘 기록된 식단을 바탕으로 AI가 실시간으로 1문장 조언 생성

**동작 방식:**

```
앱 시작 / 홈 화면 진입
    ↓
오늘 기록된 식사 목록 로드 (AppState.todayMeals)
    ↓
프롬프트 조립 (report mode):
  "오늘 식단: {아침/점심/저녁 목록}
   총 XXkcal 섭취. 한 문장(30자 이내)으로
   오늘의 식단 조언을 작성해줘."
    ↓
Qwen3:8b → 1문장 응답 SSE 스트리밍
    ↓
홈 화면 팁 배너에 실시간 출력
```

- RAG 검색 없음 (report mode → 즉시 LLM 호출)
- 식단 기록이 없으면 일반 건강 팁 출력
- 걸음 수·운동 관련 내용 프롬프트에서 명시적 제외

## 4. 알레르기 안전 시스템 (규칙 기반)

AI 기능은 아니지만 AI 추천과 긴밀히 연동됩니다.

**단일 소스 정의:** `ai/allergens.py` → 서버(2곳) + 앱(AllergenService) 모두 동일 키워드 사용

**11개 알레르겐 카테고리:** 유제품·견과류·갑각류·밀·글루텐·계란·대두·복숭아·토마토·고등어·조개류

**적용 지점:**
1. ChromaDB 검색 단계: 알레르겐 키워드 포함 문서 필터링 (RAG 전)
2. 추천 검증 단계: `validate_and_rank_items()`에서 알레르겐 항목 제외
3. 스트리밍 후처리: 응답에 알레르겐 키워드 감지 시 ⚠️ 경고 append
4. 식단 추가 화면: 앱 내 규칙 기반 실시간 경고 배너

## 5. 영양 목표 자동 계산

**위치:** `server/common/nutrition.py` → `calculate_target_kcal()`

사용자 신체 정보(나이·성별·키·몸무게·활동량) 기반 자동 계산:

```
기초대사량(BMR) = Mifflin-St Jeor 공식
  남성: 10×체중 + 6.25×키 - 5×나이 + 5
  여성: 10×체중 + 6.25×키 - 5×나이 - 161

목표 칼로리 = BMR × 활동계수
  (비활동적: 1.2 / 가벼운 활동: 1.375 / 보통: 1.55 / 활발: 1.725)

목표별 조정:
  다이어트: -500kcal / 증량: +500kcal / 유지: 조정 없음
```

## 7. 성능 설계 결정

### 왜 파인튜닝 대신 RAG인가?

| 비교 항목 | 파인튜닝 | RAG (NutrAI 선택) |
|---|---|---|
| 최신 데이터 반영 | 재학습 필요 | DB 업데이트만으로 즉시 반영 |
| 구축 비용 | 라벨링된 대규모 데이터셋 필요 | 공공 영양 DB 활용 가능 |
| 환각(hallucination) | 모델이 임의 생성 가능 | DB에서 검색된 사실만 사용 |
| 도메인 특화 | 높음 | 프롬프트 엔지니어링으로 보완 |

### 왜 외부 API(OpenAI 등)가 아닌 Ollama인가?

- **개인정보:** 식단·건강 데이터가 외부 서버로 전송되지 않음
- **비용:** API 호출 비용 없음, 로컬 GPU/CPU 활용
- **속도:** 네트워크 레이턴시 없음 (localhost 통신)
- **오프라인:** 인터넷 없이도 동작

### temperature 설정

| 용도 | temperature | 이유 |
|---|---|---|
| 채팅·리포트·팁 | **0.6** | 자연스러운 문장, 적당한 다양성 |
| 추천 메뉴 JSON | **0.4** | JSON 구조 안정성, 오류 최소화 |

## 8. 프롬프트 상세 (실제 코드 기준)

> 모든 프롬프트는 System / User 두 레이어로 구성됩니다.  
> **System prompt** = LLM의 역할·규칙 정의 (서버에서 주입)  
> **User-turn prompt** = 실제 데이터 + 분석 요청 (Flutter 또는 서버에서 조립)

---

### 8-1. AI 코치 채팅 — System Prompt

`ai/rag_engine/rag_pipeline.py` › `SYSTEM_PROMPT`

```
한국어로만 답변하는 NutrAI 영양 코치입니다.
반드시 [참고 영양 정보]에 있는 식품 데이터를 바탕으로 추천하세요.
목록에 없는 음식은 추천하지 마세요.
알레르기 성분이 포함된 음식은 절대 추천하지 마세요.
질환이 있으면 해당 질환에 적합한 식단을 최우선으로 고려하세요.
의료적 확정 표현은 사용하지 말고 권고 표현을 사용하세요.
수치 계산은 반드시 [식단 현황]의 수치를 그대로 사용하고 임의로 계산하지 마세요.

[음식 선택 우선순위]
- 밥, 국, 찌개, 구이, 볶음, 나물 등 일반 가정식·한식 위주로 추천
- 즉석식품·가공식품·브랜드명 포함 식품 절대 금지

[영양 추론 규칙]
- 당뇨: 탄수화물·당류 제한 강조 (단백질 낮아서 좋다는 표현 금지)
- 고혈압: 나트륨 제한이 핵심 (지방이 낮아서 좋다는 단순화 표현 금지)
- 추천 이유는 [참고 영양 정보]의 수치만 근거로 사용

반드시 아래 형식으로 추천 메뉴 3개와 코칭 메시지를 답변:

**음식명** (칼로리: Xkcal)
추천 이유: 설명 1~2문장

코칭 메시지: 전체 식단 조언 1~2문장
```
