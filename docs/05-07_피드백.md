**출처:** 캡스톤디자인 발표 교수님 피드백  
**담당 메모:** @신동하

## 1. 발표 중 교수님 주요 질문

### 1-1. 식사량 기준
- 식사량 기준이 **1인분 기준인지** 질문하심.
- 음식별 영양성분을 계산할 때 `1인분`, `100g`, `1회 제공량` 중 어떤 기준을 쓰는지 명확히 설명해야 함.
- 식약처/공공 영양성분 데이터의 기준량과 앱에서 사용하는 serving_count가 어떻게 연결되는지 발표에 포함 필요.

### 1-2. 기초대사량 계산 방식
- 현재 설명이 키와 몸무게만으로 기초대사량을 계산하는 것처럼 보일 수 있음.
- 기초대사량은 키와 몸무게만으로는 정확히 계산하기 어렵고, 최소한 나이, 성별, 활동량 등의 정보가 함께 필요함.
- 추후 개선 방향으로 **인바디 입력값 연동**을 제시할 수 있음.

### 1-3. YOLO 객체 탐지 학습 데이터
- YOLO 객체 탐지 시 어떤 데이터로 학습했는지 명확히 설명 필요.
- 식약처 데이터는 주로 영양성분 정보이므로, 이미지 학습 데이터와 식약처 영양 DB가 각각 어떤 역할을 하는지 분리해서 설명해야 함.
- 예: YOLO는 음식 이미지 인식, 식약처 데이터는 인식된 음식의 영양성분 조회/분석에 사용.

### 1-4. Qwen3, RAG, 파인튜닝 여부
- Qwen3가 가입정보 파싱과 식단 추천에서 어떤 역할을 하는지 질문하심.
- 식약처 데이터의 영양 정보를 Qwen3가 직접 분석하는지, RAG 검색 결과로 받아서 추천에 활용하는지 구분 필요.
- 파인튜닝을 했는지, 프롬프트 엔지니어링/RAG/후처리로 구현했는지 등 **직접 구현한 범위**를 솔직하고 구체적으로 담을 것.

## 2. 긍정 피드백

- 데이터 흐름도는 좋다는 평가를 받음.
- 다음 발표에서도 데이터 흐름은 유지하되, 장황한 설명보다 핵심 흐름만 빠르게 보여주는 방식이 적합함.

## 3. 개선해야 할 발표 방향

### 3-1. 구체적인 시나리오 강화
- 기능 나열보다 사용자의 실제 흐름을 중심으로 설명해야 함.
- 예시 시나리오:
  1. 사용자가 온보딩에서 건강 목표, 알레르기, 질환 정보를 입력한다.
  2. 식사 사진을 촬영하면 YOLO가 음식을 탐지한다.
  3. 식약처 영양 DB에서 해당 음식의 영양성분을 조회한다.
  4. 현재까지 섭취한 영양소를 누적 분석한다.
  5. Qwen3/RAG가 부족하거나 과한 영양소를 바탕으로 다음 식단을 추천한다.

### 3-2. 프롬프트 예제 개선
- 프롬프트 예제에 사용자 정보가 동적으로 바뀌는 부분을 반영해야 함.
- 예: 목표 칼로리, 현재 섭취 칼로리, 단백질/탄수화물/지방 섭취량, 알레르기, 질환, 선호 음식.
- 단순한 고정 문장보다 “사용자 데이터가 들어가면 추천 결과가 어떻게 달라지는지”를 보여줄 것.

### 3-3. 추천 시나리오 고도화
- 현재 추천 시나리오가 간단하다는 피드백.
- 식단을 추천할 때 단순히 음식만 추천하지 말고, **현재까지 섭취한 영양소 기반의 불균형 분석**을 먼저 제시해야 함.
- 예: “오늘은 탄수화물이 충분하지만 단백질이 부족하므로 닭가슴살 샐러드를 추천합니다.”

### 3-4. 데이터 확장보다 온보딩 집중
- 음식 가짓수가 많을 필요는 없음.
- 데이터를 무리하게 늘리기보다, 온보딩에서 사용자의 건강 상태와 목표를 정확히 받아 LLM 추천 정확도를 높이는 데 집중할 것.
- 발표에서는 “많은 음식 지원”보다 “개인 정보 기반 추천 품질”을 강조하는 편이 좋음.

## 4. 다음 발표 준비 사항

### 발표 일정 및 조건
- 3주 후 발표.
- 다음 주는 깃 강의.
- 13주차 발표를 최종 발표라고 생각하고 준비할 것.
- 발표 시간은 20분.

### 발표 구성 권장 순서
1. 필요성
2. 시스템 설계
3. 시스템 설계 설명 후 시스템 아키텍처 그림 제시
4. 주요 기능
5. 구체적인 사용자 시나리오와 UI 흐름
6. AI 기반 기능 구현 방식
7. 학습 방법, 데이터 출처, 성능 또는 평가 방법

### 발표 시 주의할 점
- 시스템 아키텍처 그림을 너무 길게 설명하지 말 것.
- AI 기능은 “무엇을 만들었는지”보다 “어떻게 만들었는지”를 강조할 것.
- 학습 데이터, 식약처 데이터 활용 방식, 파인튜닝 여부, RAG 여부를 명확히 구분할 것.
- 본인이 실제로 구현한 내용과 구현하지 않은 내용을 섞어서 말하지 말 것.

## 6. 다음 발표에서 강조할 메시지

- NutrAI는 단순 음식 기록 앱이 아니라, **현재 섭취 영양소와 개인 건강 정보를 함께 고려하는 AI 식단 추천 시스템**이다.
- YOLO는 음식 인식을 담당하고, 식약처 영양성분 DB는 신뢰 가능한 영양 정보의 근거로 사용한다.
- Qwen3는 사용자 가입정보 파싱과 추천 문장 생성을 담당하며, RAG를 통해 검색된 영양 정보를 바탕으로 답변한다.
- 핵심 차별점은 많은 음식을 맞히는 것이 아니라, 온보딩 정보와 섭취 기록을 바탕으로 더 안전하고 개인화된 추천을 제공하는 것이다.
